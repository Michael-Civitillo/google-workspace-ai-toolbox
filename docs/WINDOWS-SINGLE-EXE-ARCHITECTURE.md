# Windows single-executable release: architecture

**Decision: yes, Google Workspace Open Admin can ship as one `.exe`.** Build the Next.js app in `standalone` mode, zip the output, embed the zip as an asset in a Node.js *single executable application* (SEA), and let a small launcher script inside that executable extract the app to the user's profile on first run, start the Next.js server in-process, and open the browser. The user downloads one file (about 100 MB), double-clicks it, and lands on `http://localhost:3000`.

This document is the build spec. It records what was measured in a spike against the current `main`, the constraints in the codebase that the packaging must respect, the design, the exact code and pipeline changes, and the acceptance tests. It is written so an implementer can execute it without re-deriving anything.

Everything marked **verified** was executed in a Linux sandbox against this repository at commit `3531637`. Everything marked **unverified** could not be run here (Windows-only steps) and is called out in the test plan.

## 1. What ships

| Item | Value |
|---|---|
| Artifact | `OpenAdmin-win-x64.exe` (name is a constant; change freely) plus `SHA256SUMS.txt` on the GitHub Release |
| Expected size | ~97 MB (node.exe 87.1 MB + ~10 MB compressed app payload) |
| Runtime | Node.js 22 LTS, embedded. No Node, npm, or `gws` install required on the target machine |
| First run | Console window opens, asks the operator to choose the admin password, extracts the app to `%LOCALAPPDATA%\GoogleWorkspaceOpenAdmin\app\<version>-<hash>\` (about 2,300 files), starts the server, opens the default browser at `http://localhost:3000` |
| Later runs | Skips extraction (marker file), ready in about a second, opens the browser |
| State | `%LOCALAPPDATA%\GoogleWorkspaceOpenAdmin\data\` holds `tenants.json`, `sso.json`, `app-config.json`, `audit.log`, `credentials\`, `launcher.json`, `logs\` |
| Upgrade | Download the new exe, run it. New version extracts to its own folder, data folder is untouched, old app folders are pruned |
| Uninstall | Delete the exe and `%LOCALAPPDATA%\GoogleWorkspaceOpenAdmin` |
| Stop | Ctrl+C in the console, or close the console window |
| Network | Binds `127.0.0.1` only. Nothing is exposed on the LAN and Windows Firewall does not prompt |

### 2.2 Constraints in the codebase that drive the design

**C1. All local state defaults to `process.cwd()`, and the standalone server changes cwd.**
`.next/standalone/server.js` (generated by Next) begins with `process.chdir(__dirname)`. Four stores resolve paths from `process.cwd()`:

| File | Path expression | Env override today |
|---|---|---|
| `src/lib/tenants-server.ts:26` | `path.join(process.cwd(), "tenants.json")` | none |
| `src/lib/app-config.ts:15` | `path.join(process.cwd(), "app-config.json")` | none |
| `src/lib/sso-server.ts:35` | `SSO_CONFIG_PATH \|\| path.join(process.cwd(), "sso.json")` | `SSO_CONFIG_PATH` |
| `src/lib/audit.ts:11` | `AUDIT_LOG_PATH \|\| path.join(process.cwd(), "audit.log")` | `AUDIT_LOG_PATH` |
| `src/lib/credential-files.ts:51` | `GWS_CREDENTIALS_DIR \|\| path.join(process.cwd(), "credentials")` | `GWS_CREDENTIALS_DIR` (also changes validation semantics) |

Verified consequence: in the prototype, creating a tenant wrote `tenants.json` **inside the extracted app folder**, which is versioned and disposable. Without a fix, every upgrade would silently lose tenants and onboarding state. Fix: a single `OPEN_ADMIN_DATA_DIR` base directory (section 6.1).

**C2. The CSRF check accepts exactly one Origin host in standalone mode: `localhost:<port>`.**
`src/middleware.ts` compares the `Origin`/`Referer` host with `req.nextUrl.host`. In standalone mode Next builds that URL from the *bind hostname*, not the request's `Host` header (`node_modules/next/dist/server/lib/router-utils/resolve-routes.js:116`, `next-server.js` `attachRequestMeta`), and `NextURL` then rewrites any loopback hostname (`127.x.x.x`, `[::1]`, `localhost`) to `localhost` (`node_modules/next/dist/server/web/next-url.js:15-19`). Measured with `POST /api/auth/login`:

| `HOSTNAME` env (bind address) | Origin `http://localhost:P` | Origin `http://127.0.0.1:P` | Origin `http://<LAN IP>:P` |
|---|---|---|---|
| unset (server.js defaults to `0.0.0.0`) | 403 | 403 | 403 |
| `127.0.0.1` | **200** | 403 | n/a |
| `localhost` | **200** | 403 | n/a |

Consequences: the launcher must set `HOSTNAME=127.0.0.1` **and** open the browser at `http://localhost:<port>`, never `http://127.0.0.1:<port>`. A user who types `127.0.0.1` gets a 403 on login. Section 6.4 adds loopback-alias tolerance to the middleware so both spellings work. Side finding, outside this project's scope but worth a README note: anyone running the standalone output without `HOSTNAME` (typical Docker) gets a 403 on every mutating request.

**C3. The `gws` CLI is not needed at runtime.**
`src/lib/gws.ts` exports `gws()` with zero callers; the only live use is `checkGwsStatus()` behind `GET /api/gws/status`, consumed by the dashboard, Setup and Onboarding pages for a status card. All Workspace operations go through `googleapis` in `src/lib/admin-sdk.ts`. The exe therefore does **not** bundle `gws`. The UI copy that tells users to install it must be softened in packaged mode (section 6.3).

**C4. `next/image` is used once (the sidebar logo, an SVG).** Next 16 traces `sharp` into the standalone output for the image optimizer. Setting `images.unoptimized: true` keeps behaviour identical for an SVG and lets the payload drop the 34 MB of platform-specific native libraries (section 6.2). Verified: with `unoptimized: true` the logo served 200 from the prototype.

**C5. Turbopack traces the whole project because of `path.join(process.cwd(), "credentials")`.** The build printed "Encountered unexpected file in NFT list" via `src/lib/credential-files.ts`, and `package.json`, `package-lock.json`, `tsconfig.json`, `components.json` were copied into the standalone root. Harmless, but the data-dir refactor should use a function call plus `/* turbopackIgnore: true */` so tracing stops (section 6.1).

**C6. Shutdown.** Next's `start-server.js` installs its own `SIGINT`/`SIGTERM` handlers that close the listener and exit. In the prototype the process did not exit within 1.5 s of `SIGINT` but had exited when checked later. The launcher owns shutdown with a bounded grace period (section 8).

**C7. Session cookie is `Secure` in production** (`src/lib/auth.ts:304`). Chromium, Edge and Firefox accept `Secure` cookies on `http://localhost` (it is a trustworthy origin), so login over plain HTTP on localhost works. This is the second reason to open `localhost`, not `127.0.0.1`. Verify in Edge and Firefox on Windows (test plan, section 10.4).

## 3. Options considered

| Option | Single file | Runtime that executes Next | Build host | Est. size | Assessment |
|---|---|---|---|---|---|
| **Node SEA launcher with embedded payload (chosen)** | yes | real Node.js, in-process | Windows runner (signtool), or Linux with `osslsigncode` | ~97 MB | Verified end to end on Linux. One runtime, no dropped executables, Node-documented flow. Toolchain is npm only |
| Bun `--compile`, Next runs on Bun in-process | yes | Bun | any OS (cross-compiles) | ~125 MB | One command and native Windows icon/version flags. Smoke-tested OK on Linux, but the auth gate is Next middleware running in Next's `vm`-based sandbox and Bun's `node:vm` is incomplete. Not worth the risk for a security boundary. Keep as plan B; the launcher is written runtime-agnostic (section 8.6) |
| Bun `--compile` launcher + `node.exe` inside the payload | yes | real Node, child process | any OS | ~155 MB | Two runtimes, drops and executes a second `.exe` (more AV heuristics), biggest file |
| Go or Rust stub + payload (`node.exe` + app) | yes | real Node, child process | any OS | ~60 MB | Smallest, but adds a second language toolchain to a TypeScript repo and also drops an executable |
| Electron "portable" or Tauri | yes | Chromium or WebView2 + Node | Windows | 150 MB+ / 20 MB + sidecar | Gives a native window, but still needs one of the above for the server. A later "desktop shell" step, not the packaging solution |
| `pkg`, `nexe` | yes | patched Node | — | — | Archived or stale; Next.js unsupported |
| Zip with `node.exe` + `start.cmd` | no | real Node | any | ~60 MB | The one-day fallback if SmartScreen or AV friction with SEA binaries proves unworkable |

Why SEA wins: it is the only option that keeps a single real Node runtime, never writes an executable to disk at runtime (only `.js`/`.json`/`.css` files are extracted), needs no new toolchain, and its mechanics were verified here with the actual app payload.

## 4. Architecture

### 4.1 Components

```
OpenAdmin-win-x64.exe  (= node.exe + injected SEA blob)
├── launcher.cjs        bundled by esbuild from packaging/launcher/src/*.ts
└── assets/payload.zip  built by packaging/build-payload.mjs from:
    ├── .next/standalone/**   (server.js, .next/server/**, node_modules/** minus sharp/@img)
    ├── .next/static/**       (copied to .next/static — Next does not do this for you)
    └── public/**             (copied to public — same)

%LOCALAPPDATA%\GoogleWorkspaceOpenAdmin\
├── app\
│   └── 0.2.0-1a2b3c4d5e6f\     extracted payload; name = version + 12 hex of payload sha256
│       ├── .complete           marker: written last, contains ISO timestamp + hash
│       ├── server.js
│       ├── .next\ node_modules\ public\
└── data\                        OPEN_ADMIN_DATA_DIR
    ├── launcher.json            { version, port, password, sessionSecret, openBrowser }
    ├── launcher.env             optional KEY=VALUE lines merged into the server env
    ├── launcher.lock            { pid, port, startedAt } while running
    ├── logs\launcher.log        rotating copy of console output
    ├── tenants.json  sso.json  app-config.json  audit.log
    └── credentials\             relocated service-account keys (config import)
```

### 4.2 Runtime sequence

1. **Parse args and env** (`--port`, `--data-dir`, `--no-browser`, …; section 8.2). Resolve `root` and `dataDir`; create `dataDir`.
2. **Load launcher config** from `data/launcher.json`, then `data/launcher.env`, then process env, then CLI flags (later wins). If no password from any source: if stdin is a TTY, prompt twice with echo off and save; otherwise generate a random one, print it once, save it. Generate and persist `sessionSecret` on first run.
3. **Single-instance check.** Read `launcher.lock`; if its pid is alive and `GET http://127.0.0.1:<port>/login` answers, print "already running", open the browser (unless `--no-browser`) and exit 0. Otherwise if the port is in use by something else, exit 3 with a message naming `--port`. Doing this before starting Next matters: Next calls `process.exit(1)` on `EADDRINUSE` with `allowRetry: false`.
4. **Ensure the app is extracted.** Compute `appDir = root/app/<version>-<hash12>`. If `appDir/.complete` exists, done. Else extract the zip (pure JS, `fflate`) into `appDir.tmp-<pid>`, write `.complete`, rename to `appDir`. Retry `EBUSY`/`EPERM` writes and the final rename with backoff (Windows AV). Prune other `root/app/*` directories best-effort after a successful start.
5. **Set the server environment** (section 4.3) on `process.env`.
6. **Start Next in-process:** `createRequire(appDir/server.js)(appDir/server.js)`. Next's `startServer` binds `127.0.0.1:<port>`.
7. **Wait for readiness:** poll `GET /login` until 200 (timeout 60 s, exit 5 on failure). Write `launcher.lock`.
8. **Announce and open:** print the URL, data dir, and "Press Ctrl+C to stop". Open `http://localhost:<port>` via `cmd /c start "" <url>`.
9. **Run until signal.** On `SIGINT`/`SIGTERM`: log, remove `launcher.lock`, give Next 2 s to close, then `process.exit(0)`.

### 4.3 Launcher to app environment contract

| Variable | Set by launcher to | Why |
|---|---|---|
| `NODE_ENV` | `production` | server.js sets it too; set early for any module that reads it |
| `PORT` | chosen port (default 3000) | read by server.js |
| `HOSTNAME` | `127.0.0.1` (or `--host`) | bind address **and** canonical host for CSRF (C2) |
| `APP_PASSWORD` | from launcher.json / env / flag | required by `src/middleware.ts`; app refuses to serve without it |
| `APP_SESSION_SECRET` | persisted random 32 bytes hex | sessions survive restarts; decoupled from password |
| `OPEN_ADMIN_DATA_DIR` | `data` dir | new; base for all stores (C1) |
| `AUDIT_LOG_PATH` | `data/audit.log` | existing override, set explicitly for clarity |
| `SSO_CONFIG_PATH` | `data/sso.json` | existing override |
| `OPEN_ADMIN_PACKAGED` | `1` | UI shows desktop-build copy, `gws` marked optional (C3) |
| `NEXT_TELEMETRY_DISABLED` | `1` | no telemetry from a desktop tool |
| pass-through | `GOOGLE_WORKSPACE_ADMIN_EMAIL`, `GOOGLE_WORKSPACE_CLI_CREDENTIALS_FILE`, `GOOGLE_GENERATIVE_AI_API_KEY`, `GEMINI_MODEL`, `GWS_CREDENTIALS_DIR`, `APP_SSO_DISABLED`, `TRUSTED_PROXY`, `GWS_BIN` | existing app knobs; `launcher.env` is the friendly way to set them |

Never set `GWS_CREDENTIALS_DIR` by default: it changes credential-path validation semantics (`src/lib/validate.ts:validateCredentialsFilePath`) and would reject keys stored elsewhere.

These are small, backward compatible, and useful even without the exe. Land them first as their own PR.

### 6.1 `src/lib/data-dir.ts` and store refactor

```ts
import path from "node:path";

/**
 * Base directory for everything Open Admin persists locally: tenants.json,
 * app-config.json, sso.json, audit.log and relocated credential files.
 *
 * Defaults to the process working directory so `npm run dev` / `npm start`
 * behave exactly as before. The packaged desktop build sets
 * OPEN_ADMIN_DATA_DIR to a per-user application-data folder, because the
 * standalone server chdir()s into a versioned, disposable app directory.
 */
export function dataDir(): string {
  const configured = process.env.OPEN_ADMIN_DATA_DIR?.trim();
  return configured ? path.resolve(configured) : process.cwd();
}

export function dataPath(...segments: string[]): string {
  // turbopackIgnore stops output-file tracing from treating this as a
  // static reference into the project root (see build warning in C5).
  return path.join(/* turbopackIgnore: true */ dataDir(), ...segments);
}
```

Edits (one line each, keep the existing env overrides winning):

| File | Change |
|---|---|
| `src/lib/tenants-server.ts:26` | `const STORE_PATH = dataPath("tenants.json");` |
| `src/lib/app-config.ts:15` | `const STORE_PATH = dataPath("app-config.json");` |
| `src/lib/sso-server.ts:35` | `process.env.SSO_CONFIG_PATH \|\| dataPath("sso.json")` |
| `src/lib/audit.ts:11` | `process.env.AUDIT_LOG_PATH \|\| dataPath("audit.log")` |
| `src/lib/credential-files.ts:51` | `: dataPath("credentials")` |
| `README.md` env table, `.env.example` | document `OPEN_ADMIN_DATA_DIR` |

### 6.4 Loopback-alias tolerance in `src/middleware.ts`

Replace the two `originHost !== expectedHost` / `refererHost !== expectedHost` comparisons with `!sameOriginHost(expectedHost, originHost)`:

```ts
const LOOPBACK_HOST = /^(localhost|127(?:\.\d{1,3}){3}|\[::1\])$/i;

function splitHostPort(hostport: string): [string, string] {
  const i = hostport.lastIndexOf(":");
  // "[::1]:3000" → ["[::1]", "3000"]; "localhost" → ["localhost", ""]
  if (i === -1 || hostport.endsWith("]")) return [hostport, ""];
  return [hostport.slice(0, i), hostport.slice(i + 1)];
}

/**
 * Same-origin test for the CSRF check. Next canonicalises loopback IPs to
 * "localhost" in req.nextUrl, so a user browsing http://127.0.0.1:3000 sends
 * Origin 127.0.0.1 against an expected host of localhost. All loopback
 * spellings on the same port are the same server, so treat them as equal.
 */
function sameOriginHost(expected: string, actual: string): boolean {
  if (expected === actual) return true;
  const [eh, ep] = splitHostPort(expected);
  const [ah, ap] = splitHostPort(actual);
  return ep === ap && LOOPBACK_HOST.test(eh) && LOOPBACK_HOST.test(ah);
}
```

Port must still match, so another local app on a different port cannot pass. Acceptance: with `HOSTNAME=127.0.0.1 node .next/standalone/server.js`, `POST /api/auth/login` returns 200 with Origin `http://localhost:3000` **and** `http://127.0.0.1:3000`, and 403 with `http://127.0.0.1:3001` or `http://evil.example`.

## 7. Packaging pipeline (Phase 2)

### 7.1 `packaging/build-payload.mjs`

1. Assert Node ≥ 22.12 and that `.next/standalone/server.js` exists (else print `npm run build` and exit 1).
2. `rm -rf packaging/dist/payload`, copy `.next/standalone/**` to it, copy `public/**` to `payload/public`, copy `.next/static/**` to `payload/.next/static`. (Verified necessary: the standalone output does not include either.)
3. Prune `payload/node_modules/sharp`, `payload/node_modules/@img`, and any stray root files not needed at runtime (`package-lock.json`, `tsconfig.json`, `components.json`, `next.config.ts`). Keep `package.json` (Next reads it for the version banner).
4. Zip with `fflate.zipSync` (level 9, forward-slash paths, no directory entries needed) to `packaging/dist/payload.zip`. Write `packaging/dist/payload.json` with `{ version (from package.json), sha256, fileCount, bytes, zipBytes, builtAt }`.
5. Print the numbers. Fail if the zip exceeds 40 MB (guard against sharp creeping back in or the project being traced whole).

### 7.2 `packaging/build-launcher.mjs`

1. esbuild: `packaging/launcher/src/main.ts` → `packaging/dist/launcher.cjs`, `--bundle --platform=node --target=node22 --format=cjs`, `--define:__APP_VERSION__='"<version>"'`, `--define:__PAYLOAD_SHA256__='"<sha256>"'`. Verified working shape: the prototype bundle was 75 KB.
2. Write `packaging/dist/sea-config.json`:

```json
{
  "main": "launcher.cjs",
  "output": "sea-prep.blob",
  "disableExperimentalSEAWarning": true,
  "useCodeCache": false,
  "assets": { "payload.zip": "payload.zip" }
}
```

3. Run `node --experimental-sea-config packaging/dist/sea-config.json` from `packaging/dist`. Output: `sea-prep.blob` (about 10 MB; verified with exactly these settings). `useCodeCache: true` is an optional startup optimisation to evaluate later; the launcher is tiny, so the gain is small, and Node documents restrictions on dynamic `import()` in cached main scripts that would conflict with the compat shim in section 8.1.

### 7.3 `packaging/build-exe.ps1` (Windows, **unverified here**)

```powershell
$ErrorActionPreference = 'Stop'
$dist = "packaging/dist"
$exe  = "$dist/OpenAdmin-win-x64.exe"
$ver  = (node -p "require('./package.json').version")

# 1. Start from the exact node.exe that runs this script.
Copy-Item (Get-Command node).Source $exe -Force

# 2. Remove Microsoft/Node's Authenticode signature; injecting a section would
#    invalidate it anyway and an invalid signature is worse than none.
$signtool = Get-ChildItem "C:\Program Files (x86)\Windows Kits\10\bin\*\x64\signtool.exe" |
  Sort-Object FullName -Descending | Select-Object -First 1
if ($signtool) { & $signtool.FullName remove /s $exe } else { Write-Warning "signtool not found; leaving (soon-invalid) signature in place" }

# 3. Icon and version resource. rcedit rewrites PE resources; do it before postject.
node -e @"

rcedit(process.argv[1], {
  icon: 'packaging/assets/icon.ico',
  'file-version': process.argv[2] + '.0',
  'product-version': process.argv[2] + '.0',
  'version-string': {
    ProductName: 'Google Workspace Open Admin',
    FileDescription: 'Google Workspace Open Admin (single-file build)',
    CompanyName: 'Google Workspace Open Admin contributors',
    LegalCopyright: 'MIT License',
    OriginalFilename: 'OpenAdmin-win-x64.exe',
  },
}).then(() => console.log('rcedit ok'), e => { console.error(e); process.exit(1); });

# 4. Inject the SEA blob (launcher + payload asset).
npx postject $exe NODE_SEA_BLOB "$dist/sea-prep.blob" --sentinel-fuse NODE_SEA_FUSE_fce680ab2cc467b6e072b8b5df1996b2

# 5. Optional: sign. See section 11 (Azure Trusted Signing).
# & $signtool.FullName sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 ... $exe

Get-FileHash $exe -Algorithm SHA256 | ForEach-Object { "$($_.Hash.ToLower())  OpenAdmin-win-x64.exe" } | Set-Content "$dist/SHA256SUMS.txt"
```

Ordering rationale: `signtool remove` → `rcedit` → `postject` → `sign`. rcedit edits the resource section and PE headers, postject appends a new `NODE_SEA_BLOB` section and flips the fuse string; doing rcedit last has been reported to corrupt injected binaries, so keep it before injection. If rcedit fails on the ~87 MB file, ship without the icon first and fix separately; the icon is cosmetic.

## 8. Launcher specification

### 8.1 Module responsibilities

- `payload.ts`: `loadPayload(): Uint8Array`. If `require("node:sea").isSea()`, return `Buffer.from(sea.getAsset("payload.zip"))`. Else (dev run: `node packaging/dist/launcher.cjs`) read `payload.zip` next to the script. Behind the same interface, a Bun-compiled build would return `Bun.file(embedded).bytes()` (section 8.6).
- `paths.ts`: `defaultRoot()` = `%LOCALAPPDATA%\GoogleWorkspaceOpenAdmin` on Windows (fallback `~\AppData\Local`), `~/Library/Application Support/GoogleWorkspaceOpenAdmin` on macOS, `$XDG_DATA_HOME/GoogleWorkspaceOpenAdmin` or `~/.local/share/...` on Linux. **Portable mode:** if a `data` directory or a `portable.txt` file exists next to the executable, use `<exeDir>/data` and `<exeDir>/app` instead (USB-stick or shared-folder use). `appDirFor(root, version, hash)`.
- `config.ts`: load and merge (lowest to highest): `launcher.json`, `launcher.env`, `process.env`, CLI flags. Password prompt via `node:readline` with echo suppressed (write `*`), twice, minimum 12 characters. Non-TTY: `crypto.randomBytes(18).toString("base64url")`, printed once with a warning, saved. `--set-password` re-prompts and saves. Writes `launcher.json` atomically (tmp + rename) — the same pattern as `src/lib/json-store.ts`.
- `extract.ts`: `ensureExtracted(zip, appDir)`. `unzipSync` from `fflate` into `appDir + ".tmp-" + pid`; `writeFileSync` with retry on `EBUSY`/`EPERM`/`EACCES` (5 attempts, 100 ms × 2ⁿ); `.complete` marker written last; `renameSync` with the same retry; on any failure remove the tmp dir and exit 4 with the path and error. `pruneOldVersions(root, keepDir)` best-effort after start. `--reset-app-cache` deletes `root/app` before extraction.
- `instance.ts`: `readLock()`, `isAlive(pid)` via `process.kill(pid, 0)`, `probe(port)` = `GET /login` with 1 s timeout, `writeLock()`, `removeLock()`.
- `server.ts`: `applyServerEnv(cfg)` (section 4.3), `startServer(appDir)` = `createRequire(serverJs)(serverJs)`, `waitUntilReady(port, host, 60_000)`, `installShutdown()` for `SIGINT`/`SIGTERM` (2 s grace, then `process.exit`). Also the **execPath compat shim**: if `process.argv[1]` is an existing `.js`/`.cjs`/`.mjs` file, run it via `createRequire`/`import()` and return, so anything that spawns `process.execPath script.js` still works. Not needed today (no child processes observed) but cheap insurance.
- `browser.ts`: Windows `cmd /c start "" <url>`, macOS `open`, Linux `xdg-open`; detached, stdio ignored, errors logged not thrown.
- `log.ts`: timestamps, mirrors to `data/logs/launcher.log`, rotate at 1 MB, keep 5.
- `args.ts`: flags below, `--help`, `--version`, exit codes.

### 8.2 Command line

```

  --port <n>            HTTP port (default 3000; persisted to launcher.json when given)

  --root <path>         override the whole %LOCALAPPDATA%\GoogleWorkspaceOpenAdmin root (app cache + data)
  --set-password        prompt for a new admin password and save it
  --password <pw>       admin password for this run only (visible in process lists; prefer env or the prompt)
  --no-browser          do not open the browser
  --host <addr>         bind address (default 127.0.0.1). Anything else prints a warning: the app then

  --help
```

Exit codes: `0` ok or already running; `2` usage; `3` port in use by another program; `4` extraction failed; `5` server did not become ready; `130` interrupted.

### 8.3 launcher.json

```json
{ "version": 1, "port": 3000, "password": "…", "sessionSecret": "…64 hex…", "openBrowser": true }
```

Plain text, same trust level as `tenants.json` (Gemini keys) and `sso.json` (OIDC client secret) already in the same folder, protected by the per-user ACL of `%LOCALAPPDATA%`. A hashed password is not possible without an app change because `src/lib/auth.ts` compares `APP_PASSWORD` from the environment; listed as a follow-up in section 12.

### 8.4 launcher.env

Optional `KEY=VALUE` lines (comments with `#`, no quoting rules beyond trimming). Intended for `GOOGLE_GENERATIVE_AI_API_KEY`, `GEMINI_MODEL`, `GOOGLE_WORKSPACE_ADMIN_EMAIL`, `APP_SSO_DISABLED=true` (break-glass) without touching Windows system environment variables. Most users will not need it: tenants carry their own service-account path and Gemini key in the UI.

## 11. Security notes

- **Loopback only by default.** The password gate protects HTTP without TLS; binding `127.0.0.1` keeps the session cookie off the LAN and avoids the Windows Firewall prompt. `--host` is the explicit opt-out and prints why it is risky.
- **No executables are written at runtime.** Only `.js`, `.json`, `.css`, fonts and images are extracted; the Node runtime is the exe itself. This is a deliberate advantage over launcher-plus-`node.exe` designs for antivirus heuristics.
- **Secrets on disk.** `launcher.json` (password, session secret) joins `tenants.json` (Gemini keys), `sso.json` (client secret) and `credentials\` (service-account keys) in the per-user `%LOCALAPPDATA%` folder. The threat model is unchanged from the existing `npm start` deployment; document it.
- **Code signing.** An unsigned exe triggers SmartScreen on first run and may receive heuristic AV detections (SEA binaries are `node.exe` with an appended section, a pattern shared with packers). Recommended: Azure Trusted Signing (low monthly cost, GitHub Action available, `signtool sign` in `build-exe.ps1`). Until then, publish the SHA-256 and the "Run anyway" instructions, and submit false positives to Microsoft. If friction stays high, the zip fallback from section 3 costs a day.
- **Node SEA maturity.** Node documents SEA as "Active development" (stability 1.1). The API surface used here (`--experimental-sea-config`, `assets`, `sea.getAsset`, `sea.isSea`, `disableExperimentalSEAWarning`) has been stable across Node 20 to 22. Pin the Node major in the workflow and re-test on bumps.
- **`process.execPath` in a SEA is the launcher.** Nothing in Next's production server spawns Node (verified: zero child processes), and the compat shim in `server.ts` covers a future dependency that does.

## 12. Known limitations and follow-ups

- **LAN or team use.** The standalone server makes the bind hostname the canonical host (C2), so serving colleagues would require `--host <machine-name>` and everyone browsing exactly that name; `0.0.0.0` never works. The clean fix is a custom server entry that calls Next's `startServer` with `hostname: undefined` (trusting the `Host` header) plus an `APP_ALLOWED_HOSTS` allowlist in the middleware. Out of scope for v1; the existing `npm start` behind a reverse proxy remains the team deployment.
- **Hashed admin password.** Would need `APP_PASSWORD_HASH` support in `src/lib/auth.ts` (scrypt or argon2 via Web Crypto is not available; `node:crypto` scrypt is fine in API routes but `middleware.ts` only checks the signed session, so the hash would be verified only in the login route).
- **HTTP proxies.** `googleapis` honours `HTTPS_PROXY`; global `fetch` (AI SDK, `openid-client`) does not by default. Node 24 adds `NODE_USE_ENV_PROXY=1`; when the embedded Node moves to 24, have the launcher set it. Verify whether Node 22.x has the backport before relying on it.
- **Windowless mode and tray icon.** Keep the console for v1: it is the stop button and the log. A later `--tray` mode needs a small native helper or a WebView shell (Tauri), and is the natural point to revisit the "desktop shell" option.
- **Auto-update.** Optional `--check-updates` that reads the GitHub Releases API and prints a line; off by default so a desktop admin tool does not phone home unasked.
- **macOS and Linux binaries** fall out of the same pipeline (`build-bin.sh`, `codesign --remove-signature` and ad-hoc re-sign on macOS). Not requested; the Linux build already exists as the CI smoke artifact.
- **Middleware deprecation.** `next build` warns that `middleware.ts` should become `proxy.ts` in Next 16. Unrelated to packaging, but it will have to happen before the next Next major.

## Appendix A. Prototype launcher (verified on Linux)

This is the exact script that ran inside the Linux SEA binary during the spike. It is intentionally minimal (no config file, no prompt, no lock file) and is the reference for `server.ts`, `extract.ts` and `payload.ts`. Bundle: `npx esbuild launcher.cjs --bundle --platform=node --target=node22 --format=cjs --outfile=launcher.bundle.cjs`.

```js
const fs = require("node:fs");
const path = require("node:path");
const os = require("node:os");
const http = require("node:http");
const crypto = require("node:crypto");
const { createRequire } = require("node:module");
const { unzipSync } = require("fflate");

let sea = null;
try { sea = require("node:sea"); } catch { /* not available */ }
const isSea = Boolean(sea && sea.isSea && sea.isSea());

// In a SEA there is no script path in argv; user args start at index 1.
const rawArgs = process.argv.slice(isSea ? 1 : 2);
const args = {};
for (let i = 0; i < rawArgs.length; i++) {
  const a = rawArgs[i];
  if (a.startsWith("--")) {
    const [k, v] = a.slice(2).split("=");
    args[k] = v !== undefined ? v
      : (rawArgs[i + 1] && !rawArgs[i + 1].startsWith("--") ? rawArgs[++i] : "true");
  }
}

const APP_NAME = "GoogleWorkspaceOpenAdmin";
const version = args.version || "0.0.0-proto";

function defaultRoot() {
  if (process.platform === "win32")
    return path.join(process.env.LOCALAPPDATA || path.join(os.homedir(), "AppData", "Local"), APP_NAME);
  if (process.platform === "darwin")
    return path.join(os.homedir(), "Library", "Application Support", APP_NAME);
  return path.join(process.env.XDG_DATA_HOME || path.join(os.homedir(), ".local", "share"), APP_NAME);
}
const root = args.root ? path.resolve(args.root) : defaultRoot();
const dataDir = args["data-dir"] ? path.resolve(args["data-dir"]) : path.join(root, "data");
fs.mkdirSync(dataDir, { recursive: true });

function loadPayload() {
  if (isSea) return Buffer.from(sea.getAsset("payload.zip"));
  return fs.readFileSync(path.join(__dirname, "payload.zip"));
}

function ensureExtracted(zipBuf) {
  const hash = crypto.createHash("sha256").update(zipBuf).digest("hex").slice(0, 12);
  const appDir = path.join(root, "app", `${version}-${hash}`);
  const marker = path.join(appDir, ".complete");
  if (fs.existsSync(marker)) return appDir;
  const tmp = `${appDir}.tmp-${process.pid}`;
  fs.rmSync(tmp, { recursive: true, force: true });
  const t0 = Date.now();
  const files = unzipSync(new Uint8Array(zipBuf));
  let n = 0;
  for (const [name, data] of Object.entries(files)) {
    if (name.endsWith("/")) continue;
    const dest = path.join(tmp, name);
    fs.mkdirSync(path.dirname(dest), { recursive: true });
    fs.writeFileSync(dest, data);
    n++;
  }
  fs.writeFileSync(path.join(tmp, ".complete"), new Date().toISOString());
  fs.rmSync(appDir, { recursive: true, force: true });
  fs.renameSync(tmp, appDir);
  console.log(`[launcher] extracted ${n} files in ${Date.now() - t0} ms -> ${appDir}`);
  return appDir;
}

function waitForPort(port, host, timeoutMs) {
  const deadline = Date.now() + timeoutMs;
  return new Promise((resolve, reject) => {
    const tick = () => {
      const req = http.get({ host, port, path: "/login", timeout: 1000 }, (res) => {
        res.resume(); resolve(res.statusCode);
      });
      req.on("error", () => (Date.now() > deadline
        ? reject(new Error("server did not start")) : setTimeout(tick, 200)));
      req.on("timeout", () => req.destroy());
    };
    tick();
  });
}

async function main() {
  const port = Number(args.port || process.env.PORT || 3000);
  const host = args.host || "127.0.0.1";
  const password = args.password || process.env.APP_PASSWORD;
  if (!password) { console.error("[launcher] APP_PASSWORD or --password required"); process.exit(2); }

  const appDir = ensureExtracted(loadPayload());

  process.env.NODE_ENV = "production";
  process.env.PORT = String(port);
  process.env.HOSTNAME = host;
  process.env.APP_PASSWORD = password;
  process.env.APP_SESSION_SECRET ||= crypto.randomBytes(32).toString("hex");
  process.env.OPEN_ADMIN_DATA_DIR = dataDir;                       // needs section 6.1
  process.env.AUDIT_LOG_PATH = path.join(dataDir, "audit.log");    // already supported
  process.env.SSO_CONFIG_PATH = path.join(dataDir, "sso.json");    // already supported
  process.env.NEXT_TELEMETRY_DISABLED = "1";
  process.env.OPEN_ADMIN_PACKAGED = "1";

  const serverJs = path.join(appDir, "server.js");
  createRequire(serverJs)(serverJs); // runs the Next.js standalone server in-process

  const status = await waitForPort(port, host, 30000);
  const url = `http://localhost:${port}`; // must be "localhost": see constraint C2
  console.log(`[launcher] ready: ${url} (GET /login -> ${status}); data dir: ${dataDir}`);
  if (args["no-browser"] !== "true") {
    const { spawn } = require("node:child_process");
    const opts = { detached: true, stdio: "ignore" };
    if (process.platform === "win32") spawn("cmd", ["/c", "start", "", url], opts).unref();
    else if (process.platform === "darwin") spawn("open", [url], opts).unref();
    else spawn("xdg-open", [url], opts).unref();
  }
}
main().catch((e) => { console.error("[launcher] fatal:", e); process.exit(1); });
```

`sea-config.json` used: `{"main":"launcher.bundle.cjs","output":"sea-prep.blob","disableExperimentalSEAWarning":true,"useCodeCache":false,"assets":{"payload.zip":"payload.zip"}}`.
